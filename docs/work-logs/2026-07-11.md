## K2 / 피오존 / 블랙야크 — 이미지 전체 삭제

### 배경
신규 브랜드 추가 작업 전 정리 단계. 브랜드명·상품 레코드는 유지하고 기존 이미지만 전부 내린 뒤 새 이미지로 재등록할 예정.

### 확인
- 세 브랜드 이미지 URL이 전부 `pub-xxxx.r2.dev/products/...` — Cloudflare R2 저장 (Supabase 아님).
- DB `ProductImage` 레코드만 지우면 R2 실제 파일은 남는 구조 → R2 객체도 함께 삭제 필요.

### 작업 내용
1. `scripts/wipe-brand-images-r2.ts` 작성/실행 — DB에 연결된 `ProductImage` 레코드 삭제
   - K2 1,263개 / 피오존 328개 / 블랙야크 62개, 총 1,653개
   - ⚠️ 최초 실행 시 R2 자격증명(`CLOUDFLARE_ACCOUNT_ID` 등)이 `.env.local`에서 로드되지 않아(`dotenv/config`는 `.env`만 읽음) R2 삭제는 스킵된 채 DB만 삭제됨 → R2에 고아 객체 발생
2. `scripts/cleanup-r2-orphans.ts` 작성/실행 — 위 문제 복구
   - `.env.local` 명시적 로드로 R2 자격증명 확보
   - R2 버킷 `products/` 전체 리스트업 (62,200개) 후 파일명 패턴(`_K2_`, `_Piozen_`, `_YAK_`)으로 필터링
   - K2 8,910개 / 피오존 2,617개 / 블랙야크 1,257개, 총 12,784개 삭제
   - DB 연결분(1,653개)보다 R2 객체 수가 훨씬 많았던 이유: 과거 대량 업로드 시 DB에 연결되지 않은 여분 이미지가 함께 올라가 있었음

### 결과
- K2/피오존/블랙야크 3개 브랜드 이미지 DB 0개, R2 0개로 완전 정리
- 브랜드(3개)·상품(576+164+31=771개) 레코드는 그대로 유지
- `public/products/` 로컬 원본 파일은 그대로 유지 (재업로드 시 재사용 가능)

### 교훈
- `dotenv/config` 기본 로드는 `.env`만 읽는다. `.env.local` 값이 필요한 스크립트는 반드시 `config({ path: ".env.local" })`를 명시해야 함 (기존 `scripts/delete-brand-images.ts` 패턴 참고).
- 삭제 스크립트에서 외부 스토리지(R2) 자격증명이 없을 경우 "경고 후 DB만 삭제 진행"이 아니라 **중단**하는 편이 안전 — 이번엔 사후 R2 리스트업으로 복구했지만, 파일명 패턴이 없었다면 고아 객체 추적이 어려웠을 것.

## K2 / 피오존 / 블랙야크 — 상품 HIDDEN 처리 (추가 조치)

### 배경
이미지만 지운 상태로는 사이트에 품목명은 뜨는데 이미지만 안 보이는 어색한 상태가 됨. 브랜드명은 유지하되 품목 자체도 노출되지 않아야 함 — 추후 더 잘 나가는 품목 기준으로 새로 업데이트 예정.

### 사전 확인
- Explore 서브에이전트로 상품 노출 경로 전수 조사: 메인/카테고리/검색/브랜드페이지/사이트맵은 전부 `status: "ACTIVE"` 필터링 → HIDDEN/DISCONTINUED 둘 다 자동 제외됨
- 상품 상세 페이지(`/products/[slug]`)는 `status === "HIDDEN"`일 때만 명시적으로 `notFound()` 처리 (`DISCONTINUED`는 상세 URL 직접 접근 시 그대로 노출되는 허점 있음) → **HIDDEN이 정답**, DISCONTINUED는 피함

### 작업 내용
- `scripts/hide-brand-products.ts` 작성/실행 — K2/피오존/블랙야크 전체 상품 `status`를 `HIDDEN`으로 변경
  - K2 576개 / 피오존 164개 / 블랙야크 31개, 총 771개

### 결과
- 3개 브랜드 상품 전부 사이트에서 비노출 (목록/검색/상세 전부 차단), 브랜드 레코드 및 Product row는 DB에 그대로 유지 (재사용 가능한 복구/재등록 경로)
